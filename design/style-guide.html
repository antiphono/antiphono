00 — Overview

Design System

Draft — pending Ben's sign-off before applying to the site

This document defines the visual language for Antiphono.com. It codifies what already exists in styles.css and proposes the decisions that are currently implicit. Nothing here is applied to the site until approved.

Design principles

01

Outcome, not process

Every page opens with the result. Tools and methods are secondary. The design reflects this — what you see is always the most important thing on screen.

02

Nothing decorative

No gradients for atmosphere, no texture for texture's sake. Every visual decision earns its place by carrying meaning or improving readability.

03

Precision over polish

Sharp edges, tight spacing, exact alignment. The 2px border radius is a decision, not a default. Refinement comes from constraint, not ornamentation.

04

Typographic hierarchy

Sora carries all the work. One typeface, three weights. Hierarchy comes entirely from scale, tracking and weight — never from a second typeface.

05

Motion with purpose

One well-choreographed entrance outperforms ten hover effects. Motion confirms an action, reveals content, or acknowledges a state change. Nothing else.

06

Accessible by default

WCAG 2.1 AA is the floor, not the target. Contrast ratios, focus rings and reduced-motion support are wired in from the start, not audited at the end.

05 — Motion & Reveals

Motion system

Everything animates with one of three easing curves — all variants of an aggressive In-Out that accelerates fast and stops cleanly. Nothing fades. Nothing scales. Content wipes in using clip-path or translates up from below a clipped overflow. Hover each card to preview the curve.

Easing curves
Primary — Expo In-Out
cubic-bezier
(0.86, 0, 0.07, 1)
All scroll-triggered reveals: text lines, image wipes, underlines, marks, page transitions. The signature curve.
Secondary — Cubic In-Out
cubic-bezier
(0.65, 0.05, 0.36, 1)
Overlay transitions, menu open/close, accordion panels. Slightly softer than primary — for contained UI movements.
Quick — Cubic Out
cubic-bezier
(0.215, 0.61, 0.355, 1)

0.15–0.2s Colour, opacity, border — immediate hover feedback only
0.3–0.35s Accordion icons, checkbox states, quick UI toggles
0.45–0.5s Button background swap, link underline, row hover
0.8–0.9s Text line reveals, heading underlines, button arrow slides

Text line reveal

Headings and large text are split into lines. Each line sits inside an overflow-hidden wrapper. On scroll entry the text translates up from 110% to 0. Subsequent lines stagger by +0.15s per line. The wrapper clips the motion so the text appears to emerge from below the baseline.

/* Text line reveal — HTML structure */ <h1> <span class="line-w"><span class="line">Product design</span></span> <span class="line-w"><span class="line">that ships.</span></span> </h1> /* CSS */ .line-w { display: block; overflow: hidden; padding-bottom: 0.15em; /* prevents descender clip */ } .line { display: block; transform: translateY(110%); transition: transform 0.9s cubic-bezier(0.86, 0, 0.07, 1); will-change: transform; } .is-started .line { transform: translateY(0); } .is-started .line-w:nth-child(2) .line { transition-delay: 0.15s; } .is-started .line-w:nth-child(3) .line { transition-delay: 0.30s; }
Image / block reveal — clip-path wipe

Images and content blocks reveal using a clip-path polygon that wipes from the bottom edge upward. The element is fully present in the DOM — only the visible area changes. No opacity, no scale. Duration 1.3s with a 0.15s delay after the text lines have started.

Image / content block

clip-path: polygon(0 100%, 100% 100%, 100% 100%, 0 100%) → full rect · 1.3s · cubic-bezier(0.77, 0, 0.18, 1)

/* Image reveal — clip-path */ .reveal-block { clip-path: polygon(0 100%, 100% 100%, 100% 100%, 0 100%); transition: clip-path 1.3s cubic-bezier(0.77, 0, 0.18, 1); } /* Loaded state (set by IntersectionObserver) */ .reveal-block.is-started { clip-path: polygon(0 100%, 100% 100%, 100% 0, 0 0); transition-delay: 0.15s; }
Heading underline reveal

Large headings have an underline that scales in from the left on scroll entry. It is a pseudo-element set at 0.02em height — thin enough to be a rule, not a decoration. The second line delays by an additional 0.2s.

How we work

scaleX(0) → scaleX(1) · transform-origin: left · 0.9s + 0.3s delay

/* Heading underline */ .large-heading { position: relative; } .large-heading .line::after { content: ''; position: absolute; left: 0; bottom: 0.05em; width: 100%; height: 0.02em; background: currentColor; transform: scaleX(0); transform-origin: left center; transition: transform 0.9s cubic-bezier(0.86, 0, 0.07, 1) 0.3s; } .is-started .large-heading .line::after { transform: scaleX(1); } /* Stagger second line underline */ .is-started .large-heading .line-w:nth-child(2)::after { transition-delay: 0.5s; }
Scroll trigger — state classes

Animations are driven by two state classes added by an IntersectionObserver. The observer adds .is-started when an element enters the viewport and .is-complete when its transition ends. CSS defines the initial (hidden) and final (visible) states; JS only flips the class.

/* IntersectionObserver pattern */ const observer = new IntersectionObserver((entries) => { entries.forEach(entry => { if (!entry.isIntersecting) return; entry.target.classList.add('is-started'); entry.target.addEventListener('transitionend', () => { entry.target.classList.add('is-complete'); }, { once: true }); observer.unobserve(entry.target); }); }, { rootMargin: '0px 0px -10% 0px', threshold: 0.1 }); document.querySelectorAll('[data-reveal]').forEach(el => observer.observe(el)); /* prefers-reduced-motion: skip to final state immediately */ @media (prefers-reduced-motion: reduce) { [data-reveal] { transition: none !important; } [data-reveal] .line { transform: none !important; } [data-reveal] .reveal-block { clip-path: none !important; } }
Page transitions

Between pages, a full-viewport overlay wipes in with a clip-path, the new page loads, then the overlay wipes out. The overlay colour matches the destination page's accent. Duration is 0.6s in / 0.6s out. The site uses Swup for AJAX navigation — the overlay is a fixed element that Swup controls via class hooks.

/* Page transition overlay */ [data-page-overlay] { position: fixed; inset: 0; pointer-events: none; clip-path: polygon(0 0, 0 0, 0 0, 0 0); /* hidden */ transition: clip-path 0.6s cubic-bezier(0.86, 0, 0.07, 1); z-index: 100; } /* Entering: overlay covers screen */ .is-transitioning [data-page-overlay] { clip-path: polygon(0 0, 100% 0, 100% 100%, 0 100%); pointer-events: all; } /* Leaving: overlay retreats */ .is-loaded [data-page-overlay] { clip-path: polygon(100% 0, 100% 0, 100% 100%, 100% 100%); }
Motion rules
RuleHow to apply it
Wipe, don't fade Use clip-path or translateY reveals, not opacity fades. Fades feel unresolved. Wipes feel decisive.
One easing curve The Expo In-Out (0.86, 0, 0.07, 1) is the site's motion signature. Use it for everything scroll-triggered. Deviate only for quick hover feedback.
Stagger lines, not sections Within a heading, stagger each line by +0.15s. Do not stagger entire sections against each other — too much delay before content appears.
Transforms and clip-path only Animate transform, clip-path, and opacity. Never animate width, height, padding, or top/left — these trigger layout.
Observe once, remove observer Call observer.unobserve() after adding .is-started. Elements do not re-animate on scroll back.
Reduced motion @media (prefers-reduced-motion: reduce) removes all transitions and sets elements to their final state immediately. No exceptions.
will-change: transform Set on .line elements only, not on every animated element. Overuse causes GPU memory pressure.

06 — Interactions

Interaction patterns

Every interactive element has exactly one primary behaviour on hover or focus. State changes use the same easing as reveal animations — nothing is linear, nothing is instant except colour feedback.

Button: background swap + arrow slide

The primary button inverts its colours on hover. The arrow icon starts off-screen left and slides in as the background transitions. Both happen in a single 0.45s Expo In-Out transition.

07 — Voice

Writing rules

These apply to every word on the site — headings, body, alt text, button labels, meta descriptions. The tone is a senior person explaining something technical to a smart client over coffee.

RuleWhat it means
Australian English Organisation, recognise, colour, behaviour, analyse, optimise — not US spellings
No em dashes Use commas, full stops, colons or brackets instead. Never — this.
Outcome first Lead with the result. Tools and methods are secondary. Never open a page with technology.
Short sentences Plain verbs. Specific nouns. If it takes two reads, rewrite it.
No invented numbers No percentages, speed claims or figures unless real and sourced. Counter values are verified, not estimated.
Forbidden words leverage, unlock, seamless, cutting edge, revolutionise, supercharge, game changing, best in class, synergy, holistic, empower, transform (as a noun), robust, journey (unless a literal user journey)
Headings test Would a technically literate client with no design background know exactly what this heading means on first read? If not, rewrite it.

09 — Accessibility

WCAG 2.1 AA

Antiphono publicly commits to WCAG 2.1 AA on client work. The site failing its own standard is a credibility problem, not a minor oversight. Every new component is tested before it ships.

RequirementImplementation
Skip link <a href="#main-content" class="skip-link"> — first focusable element on every page
Contrast: body text 4.5:1 minimum. --white on --black is 17.9:1. --grey on --black is 4.6:1 — just passes.
Contrast: large text & UI 3:1 minimum. --grey-mid (#6A6A62) on --black is 3.1:1 — use at 18px+ or bold 14px+ only.
Focus rings Visible on all interactive elements. Never remove outline without replacing it with something equally visible.
Heading structure One h1 per page. No skipped levels. Headings describe structure, never appearance.
Keyboard navigation All interactive elements reachable by Tab. Mobile menu: focus-trapped, Escape closes, focus returns to toggle.
Alt text Meaningful alt on content images. alt="" on decorative ones. Australian English, no em dashes.
Reduced motion @media (prefers-reduced-motion: reduce) applied globally. Counters, scroll reveals and transitions all comply.
Colour alone Never use colour as the only signal. Filter active state uses both colour and border weight change.
Live regions Gallery filter state changes announced via aria-live="polite" on #galleryStatus.

What this means for Antiphono

The Fontshare palette validates the warm dark direction already in styles.css. Three concrete proposals for Ben to consider:

01

Add a mid-dark surface token

Provisional: --surface: #1E1E1A. Sits between --black and --dark-surface. Useful for hover states, selected rows, and interactive cards without reaching for a full surface elevation.

02

Warm the cream further, optionally

Current --white: #F2F1EC is already warm. Fontshare goes to #FFFFE3 for a more pronounced warmth. A small step (e.g. #F5F4EC) could push the cream towards their direction without committing to full yellow.

03

Test display type at a larger cap

Fontshare's confidence comes from scale. Antiphono's current display cap is --text-3xl via clamp. A dedicated hero class at clamp(3.5rem, 7vw, 6rem) on select pages would match the editorial confidence of the reference.

NLC / Obys Agency

Extracted from nlc.obys.agency in August 2026. Built by Obys Agency. The NLC site defines the motion and typographic approach this design system adopts: a single grotesque typeface with extreme scale contrast, aggressive Expo In-Out easing throughout, and content that wipes in rather than fades.

Colour palette not adopted — type, motion and layout approach only
Typeface extraction

NLC uses Scto Grotesk A (Schick Toikka) — a commercial condensed grotesque not available for free use. Antiphono adapts the same principles using Sora: single typeface, weight 500 throughout, hierarchy built entirely from size and tracking.

NLC valueAntiphono equivalentNote
Scto Grotesk A · weight 500 Sora · weight 500 Both are geometric grotesques. Scto is condensed; Sora is rounder. Apply tighter tracking to compensate.
Single typeface throughout Sora only No editorial serif. No mono for UI. Hierarchy from scale and tracking alone.
Extra heading: 14.6rem desktop Display: clamp(3.5rem, 8vw, 7rem) NLC scales to 146px at 1280px+. Antiphono's 1120px max-width makes ~70px the practical ceiling.
Section heading: 9.2rem desktop Section: clamp(2.25rem, 5vw, 4.5rem) NLC's proportions are steeper. Antiphono text-heavy pages need slightly more restraint.
letter-spacing: -0.05em all headings -0.05em (display) → -0.03em (sub-heading) NLC uses -0.05em at every heading level. Antiphono scales tracking with size — looser at smaller sizes.
line-height: 0.9 all headings 0.90–0.95 at display · 1.0 at sub-heading 0.9 at small heading sizes clips ascenders. Step up to 1.0 below 2rem.
Body: 1.4rem · weight 500 Body: 1rem · weight 300 NLC uses medium weight for body — works with their condensed typeface. Sora at 500 is too heavy for prose; use 300.

Mark highlight scaleY reveal Yes 1.2s · 0.25s delay. Text readable first, colour arrives second.
Button arrow translateX reveal Yes 0.8s · arrow enters from left on hover.
Page transition clip-path overlay Aspirational Requires Swup or equivalent AJAX navigation. Not implemented yet — document for when navigation is revisited.
Custom cursor No NLC uses a custom cursor. Antiphono does not — adds complexity without matching benefit on a text-heavy site.
Lenis smooth scroll No Smooth scroll conflicts with native browser behaviour and causes accessibility issues. Not adopted.
Layout extraction
NLC patternAntiphono approach
3px solid top border on each section Adopt. A single heavy rule separating sections is cleaner than margin alone.
Left sidebar: single letters stacked vertically (N · L · C) Not adopted directly. The fixed left strip is brand-specific. Antiphono could use a vertical section label strip on case study pages.
Section number badges ("1:", "2:", "3:") Adopt. Small numbered labels in a dark box before each section heading give scannable structure to long pages.
Two-column section layout: label column + content column Adopt. Section label / eyebrow in narrow left column (~25%), content in wide right column (~75%). Used on how-we-work and case study pages.
Data displayed as full-width table rows with 1px horizontal rules Adopt. Numbers, stats, portfolio items — all as ruled rows, not cards. Cleaner at scale.
Full-viewport-height hero sections Partial. Antiphono hero fills the viewport above the fold but does not scroll-lock.
20px horizontal page padding (mobile) · container at md Antiphono uses --gutter (64px desktop · 24px mobile). Keep existing token.
No border-radius on buttons or interactive elements Adopt. --radius: 2px remains for internal UI. Buttons and row elements: 0 border-radius.
