Antiphono design system

Everything the site is built from: the tokens, the primitives, the components, the motion and a library of responsive sections you can paste into a new page. This page loads /styles/system.css, the same stylesheet the site loads, so what you see below is the live system rather than a picture of it.

Values marked in red are read from the running stylesheet when this page loads. If a token changes, the number here changes with it. Everything else is written down, and the written-down parts are the ones that can go stale, so treat the red numbers as the truth.

01

Principles

Five rules that decide most arguments before they start.

PrincipleWhat it means in practice
Ground firstEvery section declares whether it sits on a light or a dark ground with data-theme. Text colour, header colour and button colour all follow from that one attribute. Never set a text colour to fix a contrast problem: set the ground.
Flat by defaultDepth comes from ground colour and hairlines. A shadow is reserved for something that genuinely floats, which on this site is a modal, a pinned card and the deck. Three shadows exist and that is the whole set.
Type carries the designOne face for headlines, one for body, one weight for every heading. The visual interest comes from scale and space, not from weight, colour or decoration.
Motion is a reveal, not a performanceContent enters once as you reach it and then stays put. Nothing loops, nothing bounces, nothing moves on hover except by a couple of pixels. Every animation has a reduced-motion answer.
Readable with JavaScript offBody content lives in the HTML. JavaScript adds reveals, the menu, the cursor and the gallery. A page with scripts blocked is plain but complete.

The accent does not pass at body size. --signal-red measures 4.26:1 on the light ground and 4.00:1 on the dark one. That clears the 3:1 a large heading or a UI element needs, and misses the 4.5:1 body text needs, on both. No single red clears 4.5:1 on both grounds: darken it enough for light and it fails on dark, and the reverse. So the accent takes a per-ground pair the way the ink tokens do. Use --signal-red for a heading, a rule or an icon, and the ink pair for anything at body size or smaller. The red numbers on this page use --signal-ink-light for exactly this reason.

The highlight. This is the block behind selected text. It used to be declared three times, near-black on one component set and white on the other two, and the white one won: selecting text on a light section painted a white block on a near-white ground and the selection disappeared. There is one rule now, in the signal red with white text. Measured: white on the red reads at 4.69:1, and the red block sits between 4.0:1 and 4.69:1 against every ground in the system, so it is visible on black and on white. Try selecting this paragraph, then select something in the dark demo further down.

Do

  • Set data-theme on the section and let colour inherit.
  • Use the signal red for one thing at a time, never as a decorative fill.
  • Check body text at 4.5:1 and large text at 3:1 before calling a section finished.

Do not

  • Hardcode a hex. If the colour is not in this section, it is not in the system.
  • Use colour alone to carry meaning, including in filter and tab states.
  • Introduce a second accent. One is the point.

03

Typography

Two faces. Helvetica Neue sets every heading, Inter sets body on the current components and Sora still sets body on the pages waiting to be rebuilt. Every heading is 600 and sentence case, on every page, with no exceptions.

Known limit. Helvetica Neue has no semibold on macOS, only Medium 500 and Bold 700, so a 600 request resolves to Bold. The stylesheet says 600 and the type renders Bold. It is also a system face, so it renders differently on Windows and Android. Self-hosting a display face is an open decision.

Do

  • Write headings sentence case in the markup. No text-transform on a heading.
  • Keep one h1 per page and never skip a level.
  • Let headings describe structure. If you want something to look big, pick a bigger class, do not promote it to h2.

Do not

  • Introduce a third weight. Everything is 400 body, 600 heading, 500 labels.
  • Use Title Case anywhere except proper nouns.
  • Set a font size in pixels. Use a token.

04

Space

One ramp, ten steps, roughly geometric. Pick a step, never a number in between.

Read this before using the small steps. Two token blocks used to declare --s-4 and --s-8 with different values and the second silently won, so --s-4 is 24px and --s-8 is 96px, not 4px and 8px as the names suggest. The 4px and 8px steps are --s-1 and --s-2. The names are misleading and are kept because changing them would move spacing on every page. Read the computed column, not the name.

Do

  • Use --section-y for the space above and below a section.
  • Use --gutter for the page edge, never a fixed padding.
  • Space with the ramp, then stop. Most layouts need three steps, not eight.

Do not

  • Write margin: 37px. If the ramp cannot do it, the layout is wrong.
  • Assume a token's name matches its value. Check the table.

Breakpoints

The system is fluid first: clamp() handles most of the range and breakpoints handle the moments where a layout has to change shape rather than size. Four matter.

WidthNameWhat changes
1100pxNavigationDesktop nav gives way to the burger. Both sides of this switch are aligned to the same number so there is never a gap where neither is reachable.
900pxTwo to one columnSplit layouts stack. Header nav and CTA hide, burger shows.
860pxComponent reflowThe busiest breakpoint. Cards, rows and grids drop to one column.
700px and 560pxFine tuningType steps down and padding tightens. Avoid adding new rules here: prefer widening a clamp().

Test at 360, 768, 1024, 1280 and 1800. The last one matters because .container-x caps and the page stops filling.

Elevation

Four levels, and level 0 is the answer most of the time. This system separates things with ground colour and hairlines, so a shadow means the element genuinely floats above the page.

0. Flat
--elev-0
The default. Separate with a hairline or a change of ground.
1. Inset rule
--elev-1
A hairline drawn as a shadow so it does not affect layout. Cards and cells.
2. Lifted
--elev-2
Something that sits over content: a pinned panel or a sticky card.
3. Floating
--elev-3
The deck and the modal. One per screen, never two.

Glass

Backdrop blur is used sparingly and only where content passes behind a control: the sticky bar on this page, the mobile menu ground and the tab pill. It is never applied to a full width bar, which was a deliberate call. Blur radius sits between 12px and 20px. Always pair it with a translucent fill, because blur alone fails on browsers that do not support it.

08

Motion

Content reveals once as you reach it, then stays still. Hover moves a couple of pixels. Nothing loops except the marquee, and that stops under reduced motion like everything else.

Durations

TokenValueUse for
--t-hoverHover and focus states. Anything the pointer causes directly.
--t-buttonA control changing state: fill, border, label roll.
--t-textA line of type revealing.
--t-mediaAn image or video mask opening.
--t-sectionA whole section arriving. Use rarely.
--d-fast / --d-base / --d-slowThe index components' equivalent ramp. --d-base drives every data-anim reveal.
--staggerDelay between siblings in a staggered group.

Easings

TokenCurveCharacter
--ease-soft / --e-outThe default. Fast out, long settle. Use unless you have a reason.
--ease-editorialSlow in and slow out. For type and masks that should feel deliberate.
--e-expoThe most aggressive settle. Clip paths and reveals.
--ease-mechanical / --e-inoutSymmetrical. Things that move and come back.

Do

  • Animate transform and opacity. Nothing else is cheap.
  • Reveal once. Use unobserve so a section does not re-animate on the way back up.
  • Give every animation a reduced-motion branch that shows the final state immediately.

Do not

  • Animate width, height, top or left.
  • Add motion to something that already moves. One idea per section.
  • Leave will-change on after the animation is done.

Circle action

The round outline control used inside feature cards. Reserved for a card's single action.

Media mask

.media-mask clips an image and opens it on scroll. Wrap the figure, never the img itself: transforms applied straight to an image fight the hover zoom on work cards, which is a bug this system has already had once.

Placeholder

.ph is the standing-in surface for media that does not exist yet. It is deliberately obvious. Never ship a page with one still in it, and never replace one with stock photography.

Skip link

.apex-skip is the first focusable element on every page and targets the page's main. Tab into this page to see it. It is the one primitive where a silent failure is an accessibility defect, so test it with the keyboard after any header change.

Behaviour contracts

The system is driven by data attributes rather than by classes wired to JavaScript. Set the attribute in the markup and /scripts/apex.js picks it up. Nothing here renders content: every one of these is an enhancement over markup that already reads.

AttributeGoes onWhat it does
data-themesection, footer"light" or "dark". Sets the section's ground and its ink, and tells the fixed header what it is passing over so it can invert. Required on every section. This is the single most important attribute in the system.

The ground rule is wrapped in :where() so it adds no specificity: any component that paints its own ground keeps it, and this only fills in sections that would otherwise have painted nothing. Until 25 August it set the ink alone, which meant a section could declare itself dark, take light text, and sit on whatever the page background happened to be.
data-animany elementReveals on scroll. Values: up, down, left, right, fade, scale, clip. Starts at opacity 0 and gains .in when it enters the viewport, once.
data-staggera parentNumbers its data-anim children through --i so they arrive in sequence, --stagger apart.
data-cursorinteractive elementsGrows the custom cursor over the element. Pointer devices only.
data-cursor-labelany elementPuts a word inside the cursor, for example Explore or Play.
data-header-theme.apex-headerWritten by JavaScript, not by you. Set the initial value to match the first section so the header is right before the first frame.
data-menu-open / data-menu-closebuttons and linksOpens and closes #apex-mobile-menu. Put data-menu-close on every link inside the panel.

What JavaScript is responsible for

One file, /scripts/apex.js, running one module per component. Every module is a no-op on a page without its markup, so a page only pays for what it uses. GSAP with ScrollTrigger and Lenis load from a CDN ahead of it. If any of the three fails to load the page still reads, the menu still opens and the header still inverts, because the header falls back to a scroll listener.

Reduced motion

Under prefers-reduced-motion: reduce, Lenis does not initialise, every data-anim element renders in its final state, the marquee stops and transitions are removed. This is not optional and it is not a later pass. Test it by turning on Reduce Motion in the operating system and reloading.

Page components

Section patterns the library did not already cover, added while building the single page homepage. All unscoped and tokenised, so any page can use them.

ClassWhat it is, and what to watch
.secnavSticky section navigation. Real anchors to real ids, so with JavaScript off it is simply always visible and every link works. The script adds the appear-after-hero behaviour, the current-section highlight and mirrors the header's ground. The current item is marked with a rule as well as a colour, because colour alone must not carry state.
.logo-gridClient logos. Monochrome by filter so mixed source files still read as one set, optically sized rather than mathematically equal, static with no carousel. Every logo needs alt text with the company name.
.svc-groupA named service group: heading, one line on what it is, then a dot separated list.
.gainA numbered benefit block. Rule on top, ( 01 ) label, heading, one paragraph.
.phaseA process stage. Same shape as .gain without the number.
.duoTwo column comparison. .duo__col--machine sets in the interface face and .duo__col--human in the display face, so the difference reads before the words do.
.factsA row of two to four figures with a qualifier under each. Never put an unattributed number in one.
.bookingThird party booking embed. Never loads on page load: it loads when someone asks for it, which keeps the script and its cookies off the page until there is consent, and keeps a heavy embed out of the performance budget. It times out after eight seconds into a real link rather than a spinner, and the email beside it is always present rather than a fallback that appears on failure.
.vision__headline--wideA hero whose line breaks are written rather than wrapped. Its size is derived from the longest written line rather than taken from the scale. If the copy changes, remeasure.

On sizing type from copy. .vision__headline--wide breaks the usual rule that type comes from the scale. The hero has three written lines and the break points are part of the design, so the size has to be whatever holds the longest of them. Measured: the line fills the measure at 6.0vw at every viewport, so the rule is set at 5.9vw with a floor and a cap. Below about 470px the floor takes over and the first line wraps, which is the right trade because 22px is not display size. This is a deliberate exception, not a pattern to copy.

12

Section library

Responsive sections, ready to paste into a page. Each one is complete markup: it needs no new CSS and no new JavaScript, only /styles/system.css and /scripts/apex.js, which every page already loads. Swap the copy and the images and it works.

Every section carries data-theme. Alternate light and dark down a page and the header inverts as it passes over each one, with no further work. Each snippet also carries an aria-labelledby or aria-label, which is not decoration: a section landmark with no name is not much use to a screen reader.

13

Building a new page

Six steps. Follow them in order and the page will match the rest of the site without anyone reviewing it for consistency.

  1. Start from the skeleton below. It has the head, the noindex, the header, the mobile menu, the footer and the scripts in the right order.
  2. Paste sections from the library. Alternate data-theme so the page has rhythm and the header has something to respond to.
  3. Set the initial data-header-theme on the header to match your first section, so the header is correct before JavaScript runs.
  4. Write the copy in sentence case, Australian English, no em dashes. Read every heading and ask whether a technically literate client with no design background would know what it means on first read.
  5. Check the page: one h1, no skipped heading levels, alt text on content images, alt="" on decorative ones, and the skip link reaching main by keyboard.
  6. Check it at 360, 768, 1024 and 1800, then with Reduce Motion on, then with JavaScript disabled.

Rules that are not negotiable

Every page

  • Keeps noindex, nofollow until Ben removes it at launch.
  • Has one h1 and no skipped heading levels.
  • Reads with JavaScript disabled.
  • Never links to /reports.

Never

  • Add a bundler, a build step or an npm dependency.
  • Render body content with JavaScript.
  • Invent a statistic, a client quote or a case study figure.
  • Use stock photography to fill space.
